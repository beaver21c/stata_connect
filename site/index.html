시작하기

고른 방법의 탭을 누르면 해당 순서가 보임.

  1. Claude 데스크톱 앱 설치·로그인

    claude.com/download에서 Windows용 앱을 받아 설치하고 Pro 이상 계정으로 로그인.

  2. 파일 생성 기능 켜기
    Settings›Capabilities›Create and edit files켜기

    스킬을 쓰려면 필요함(Claude 공식 안내). 앱 버전에 따라 “Code execution and file creation”으로 보일 수 있음.

  3. 분석 스킬 추가(플러그인)
    Customize›Plugins›Add›Add marketplace

    주소 칸에 beaver21c/stata_connect 입력 → 목록의 stata-agent 추가.

  4. 설치 도우미 실행

    다운로드의 {{EXE_FILE}}을 받아 더블클릭 → 질문에 답하며 진행: Stata 확인 → (선택) Stata 화면 연동(관리자 승인 창에서 “예”, 하지 않아도 화면 없는 실행으로 분석 가능) → Claude 앱 연결(설치 도우미가 Claude 앱 설정에 Stata 도구를 직접 등록).

  5. Claude 앱 완전히 종료 후 다시 실행

    창만 닫으면 작업 표시줄 알림 영역에 남아 있을 수 있음 → 알림 영역 아이콘에서 종료한 뒤 다시 실행해야 연결이 반영됨.

  6. 새 채팅에 “Stata 연결 점검해줘” 입력

    점검표가 모두 통과로 나오면 준비 끝 → 첫 분석으로.

  1. Claude 데스크톱 앱 설치·로그인 → Code 탭

    claude.com/download에서 설치하고 Pro 이상 계정으로 로그인한 뒤 위쪽의 Code 탭을 누름. 관리자 권한·Git 설치는 필요 없음(Claude Code 공식 안내).

  2. 분석 스킬 추가(플러그인)
    Customize›Plugins›Add›Add marketplace

    beaver21c/stata_connect 입력 → stata-agent 추가.

    터미널판 Claude Code: /plugin marketplace add beaver21c/stata_connect → /plugin install stata-agent@stata-connect

  3. 분석 폴더 열기

    새 세션의 작업 폴더로 빈 폴더를 고름(예: 문서\StataAgent\프로젝트1). 문서·바탕화면 전체를 고르지 않음.

  4. /stata-agent:setup 입력

    Claude가 설치 파일 받기 → 확인값 대조 → Stata 확인 → 폴더 준비 → 연결 등록을 차례로 진행하며 명령마다 승인을 요청함. 명령 내용을 읽고 “허용”. Stata 화면 연동을 원하면 관리자 승인 창에서 “예”.

  5. 새 세션 시작 → “Stata 상태 확인해줘”

    같은 폴더로 새 세션을 열고, stata 서버 사용을 묻는 창에서 허용. 이후 첫 분석으로.

플러그인 자동 갱신과 Code 탭의 플러그인 사용은 공식 문서 확인 사항, 위 순서 전체의 실제 화면 시험은 진행 전.

  1. Codex 앱 설치·로그인

    Microsoft Store에서 “Codex”를 찾아 설치하고 ChatGPT Plus 이상 계정으로 로그인.

    OpenAI 공식 안내: developers.openai.com/codex/app

  2. 설치 도우미 실행

    다운로드의 {{EXE_FILE}}을 더블클릭 → 질문에 Enter. Codex 설정과 분석 스킬이 자동으로 들어감(기존 설정은 백업). Stata 화면 연동을 고르면 관리자 승인 창에서 “예”.

  3. Codex 앱 완전히 종료 후 다시 실행

    창만 닫지 말고 작업 표시줄 아이콘에서 종료. 설정을 다시 읽어야 연결됨.

  4. 채팅에 “Stata 연결 점검해줘” 입력

    점검표가 모두 통과로 나오면 준비 끝 → 첫 분석으로.

자료 보호 원칙

AI가 실수로라도 원자료를 보지 않도록 설계함.

계산은 Stata가AI는 수치를 직접 계산하지 않고, 로그에 나온 값만 인용함.
원자료는 AI로 보내지 않음자료의 행을 보여 주는 명령(list·browse 등)은 실행 전에 차단됨.
실행 전 연구자 승인코드를 실행하거나 파일을 바꾸는 작업은 매번 승인 창이 뜸.
결과는 눈으로 확인AI가 연 Stata 창에서 결과를 직접 보고 이어서 작업할 수 있음.
항상 재현 가능모든 분석이 do-file로 남아 처음부터 다시 실행할 수 있음.
AI 사용 내역 기록논문 연구방법 절에 쓸 AI 사용 공개문 초안을 만들어 줌.

차단되는 것과 보내지는 것

  • 차단: 자료 행 출력(list·browse·edit), 특정 관측치 값 표시, 운영체제 명령 실행, 파일 삭제, 프로젝트 폴더 밖으로 자료 내보내기, 원자료 폴더(data) 덮어쓰기.
  • 확인 후 실행: 고유값이 대부분인 변수(아이디 등)의 빈도표, 자료 파일 내보내기 등은 이유를 설명하고 연구자 동의를 받은 뒤에만 실행.
  • AI로 보내지는 것: 요약통계, 검정 결과, 변수 이름·라벨 같은 자료 구조 정보.

이 장치는 사고를 막기 위한 안전장치이며 완전한 보안 장치는 아님. 행정자료·민감자료는 기관의 반출 기준과 승인 절차를 함께 따를 것.

자주 묻는 질문

설치가 실패했거나 잘 안 되면?

설명서에서 설치 도우미를 다시 받아 그대로 다시 실행하면 됨. 이미 맞게 된 설정은 그대로 두고, 빠진 단계만 채움(바꾸는 설정은 먼저 백업). Claude 앱이 켜져 있어 이전 버전 파일을 쓰는 중이어도 교체되며, Claude 앱을 완전히 종료한 뒤 다시 실행하면 새 버전으로 바뀜. 화면에 “실패”가 남으면 그 줄의 안내를 따름.

Claude 앱에 Desktop Commander가 켜져 있어요

Desktop Commander는 Claude가 PC에서 명령을 실행하고 파일을 읽게 해 주는 도구임. 켜져 있으면 Claude가 Stata 도구를 거치지 않고 Stata를 직접 실행하거나 data 폴더의 자료 파일을 열 수 있어 원자료 보호가 무력화됨. 설치 도우미는 Desktop Commander가 Stata 실행파일을 실행하지 못하도록 차단 목록에 추가함(이전 설정은 백업). 다만 이 차단은 실행파일 이름으로만 막는 사고 방지 장치라 우회될 수 있고, 파일 읽기는 막지 못함 → Stata 분석 대화에서는 Desktop Commander를 끈 상태로 사용할 것.

“시험판”은 무슨 뜻인가요?

설치 파일은 저장소의 자동 점검(Windows에서 빌드 후 Stata 없이 연결·도구 목록·차단 규칙 시험)을 통과했지만, 실제 Stata(17·18·19)와 Claude·Codex 앱에서의 시험은 아직 진행 전이라는 뜻. 시험 결과는 소스 저장소의 docs/IMPLEMENTATION_STATUS.md에 기록됨.

설치할 때 “Windows의 PC 보호” 파란 창이 뜨면?

시험판은 코드 서명 인증서가 없어 이 창이 뜰 수 있음. 이 페이지에서 받은 파일인지(필요하면 확인값 대조) 확인한 뒤 “추가 정보 → 실행”을 누름. 기관 PC에서는 보안 프로그램이 막을 수 있으므로 전산 담당자에게 예외 등록을 요청.

방법 B에서 Claude가 실행하려는 명령을 어떻게 판단하나요?

승인 창에 실행할 명령이 그대로 보임. data 폴더의 파일을 열거나 Stata를 직접 실행하는 명령은 설치 때 넣은 실행 전 검사가 막지만, 처음 보는 명령이면 “허용” 대신 “무엇을 하는 명령인지 설명해줘”라고 물어볼 것.

“관리자 승인”은 왜 필요한가요?

AI가 Stata 창을 열고 명령을 보내려면 Stata를 Windows에 한 번 등록(COM 등록)해야 하며, 이때 관리자 권한이 필요함. 선택 사항이며, 등록하지 않으면 창을 띄우지 않는 방식(배치 실행)으로 작동하고 편집기 연동 등 일부 기능이 빠짐. 나중에 설치 도우미를 다시 실행해 등록할 수 있음.

쓰던 do-file로 이어서 작업할 수 있나요?

됨. 파일을 분석 폴더에 넣고 AI에게 “이 do-file 이어서 작업해줘”라고 하면, AI가 먼저 바뀔 내용을 보여 준 뒤 동의를 받아 준비함: 예전 한글 인코딩(cp949) 파일은 UTF-8로 바꾸고, 주석 제목(* ---- 회귀분석 ----, **# 책갈피, * 1. 자료 등) 기준으로 섹션 표지를 붙이고, list·browse 줄은 주석으로 바꿔 “직접 실행할 줄”로 알려 줌. 원본은 .stata-agent\backups에 보관되며, 고친 파일도 Stata에서 그대로 실행됨(섹션 표지는 주석 줄). 메모리 상태는 이어받을 수 없어 AI가 파일을 처음부터 한 번 실행해 복원함.

AI가 작업하는 중에 Stata 창에서 직접 작업해도 되나요?

됨. 다만 AI가 실행 중일 때는 기다릴 것. 연구자가 창에서 변수 이름을 바꾸거나 리코드·clear 등을 하면 AI가 다음 실행 직전에 이를 감지해 “연구자 조작 감지”로 알리고(바뀐 변수·값 변경 여부·창에서 친 명령), 남길 명령은 동의를 받아 do-file에 “연구자 수동 작업” 섹션으로 기록함. do-file을 편집기에서 직접 고쳐도 다음 작업 때 알아채고 그 내용을 기준으로 이어 감. (이 감지 기능은 실제 Stata 시험 전)

AI가 그래프를 직접 볼 수 있나요?

됨. AI가 그래프를 output\figures에 그림 파일(PNG)로 저장한 뒤 그림을 보고 축 제목·범례·글자 겹침을 점검해 고침. 막대·상자·히스토그램·분포·회귀 계수 그림처럼 요약한 그림은 바로 보지만, 산점도·선 그래프처럼 관측치마다 점이 찍히는 그림이나 점 옆에 값을 글자로 표시한 그림(mlabel)은 개별 값이 그림에 담기므로 AI가 먼저 동의를 구함. 그림에서 눈으로 읽은 수치는 해석에 쓰지 않음(수치는 Stata 결과에서 인용). Claude Code에서는 그림이 AI에게 전달되는 것이 공식 문서로 확인됐고, Claude 앱은 아직 시험 전(그림이 보이지 않으면 저장된 파일을 직접 열어 확인).

pystata 방식은 무엇인가요?

StataCorp가 제공하는 Python 연동(pystata)으로 Stata를 화면 없이 실행하는 보조 방식임. 기본은 Stata 창을 띄우는 방식이고, pystata는 설정에서 따로 고를 때만 씀(STATA_AGENT_BACKEND=pystata, Stata 17 이상과 PC에 설치된 Python 필요). 관리자 권한 없이 쓸 수 있고 Mac에서도 작업 내용이 이어지지만, Stata 화면이 보이지 않아 연구자가 같은 세션을 지켜보거나 Do-file Editor에서 함께 볼 수 없음. (실제 Stata 시험 전)

“라이선스가 만료됨”이라고 나오면?

Stata 라이선스를 갱신해야 함. PC에 여러 버전의 Stata가 있으면 유효한 라이선스 중 최신 버전을 자동으로 고름.

설치 후 채팅에서 Stata 도구가 보이지 않아요

① Claude 앱을 완전히 종료(창을 닫은 뒤 화면 오른쪽 아래 알림 영역에 Claude 아이콘이 남아 있으면 그 메뉴에서 종료)하고 다시 실행. ② 그래도 없으면 설치 도우미를 다시 실행해 [5/6] 단계에 “Claude 앱(…): 등록 완료”가 나오는지 확인. Microsoft Store에서 설치한 Claude 앱은 설정 파일 위치가 달라 설치 도우미가 자동으로 그 위치에 기록함. “Claude 앱: 생략 — 찾지 못함”이 나오면 Claude 앱을 한 번 실행한 뒤 설치 도우미를 다시 실행.

“차단됨”이라는 메시지가 나왔어요

자료의 행이 AI로 넘어갈 수 있는 명령이 막힌 것임. AI가 요약통계 등 다른 방법으로 바꿔 제안함. 꼭 행을 봐야 하면 연구자가 Stata 창에서 직접 실행.

오래 걸리는 분석(부트스트랩 등)은?

창 연결 방식은 명령 하나당 약 3분(180초) 제한이 있음. 오래 걸리는 분석은 AI가 백그라운드 실행(배치 모드)으로 돌리도록 안내함.

Mac에서도 되나요?

현재는 Windows 우선 개발 중. Mac 지원은 이후 단계에서 검토.

AI 사용 공개문 예시

분석이 끝나면 AI가 사용 기록을 바탕으로 초안을 만들어 줌. 반드시 연구자가 검토·수정해 사용.

본 연구의 자료 분석에는 생성형 AI(사용 도구명)를 Stata 분석 보조 도구로 활용하였다. AI는 do-file 작성·수정과 실행 로그 판독을 보조하였으며, 모든 통계량은 Stata가 산출하였다. 개별 관측치 값은 AI에 전송하지 않도록 명령 차단·출력 필터를 적용하였다. 연구자는 모든 실행 코드를 실행 전에 검토·승인하였고, 결과 해석의 최종 책임은 연구자에게 있다.

오류 알리기

연결 점검에서 만들어진 점검 보고서 파일만 첨부해 오류 알리기에 올림. 분석 로그 원문, 자료 파일 경로, 변수 값은 올리지 않음.
