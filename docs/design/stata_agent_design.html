0. 배포 전제: 아무것도 없는 PC + 월 3만원대 유료 요금제 (최우선 조건)

전제: 사용자는 MCP·스킬·Python·Node 등 아무것도 설치되어 있지 않음. 보유 자원은 ① 본인 PC에 설치된 Stata(버전 무관) ② Claude Pro 또는 ChatGPT Plus 중 하나(각 월 20달러, 약 3만원)뿐임.
목표: 개발자가 배포하는 설치 꾸러미 1개를 받아 클릭 몇 번으로 본인 PC 세팅이 끝나고, 곧바로 채팅창에서 Stata 분석을 시작할 수 있어야 함. 명령줄 입력·설정 파일 편집·런타임 설치를 사용자에게 요구하지 않음.

0.3 런타임 결정: 사용자 PC에 Python·Node를 깔지 않는 방법

방식내용장단점
A. 단일 실행파일(권고)MCP 서버(Python + pywin32, stata-gui-mcp 기반 포크)를 단일 .exe로 빌드. MCPB는 실행파일형 서버를 담을 수 있음 검색 확인(MCPB 저장소 예시에 Windows 실행파일 포함)Claude·Codex가 같은 exe 공유 / 보안 프로그램 오탐 가능성 → 코드 서명 필수 논리적 추론
B. Node.js 서버 + PowerShell COM 중계Claude 데스크톱에 Node 런타임이 내장되어 있음 1차 확인. Node 서버가 상주 PowerShell 프로세스를 띄워 New-Object -ComObject stata.StataOLEApp로 Stata 제어Claude 쪽은 런타임 무설치 / Codex 쪽은 Node 필요 여부 미확인, PowerShell 실행 정책 제약 가능
C. Python 번들(MCPB lib 폴더)의존 패키지를 번들에 포함사용자 PC에 Python 런타임 자체는 필요 검색 확인 → 전제 위배

0.4 사용자 PC에서 일어나는 설치 순서 (② 통합 설치 프로그램)

  1. 사전 점검: Stata 설치 탐색·라이선스 유효성(about 배치) → 없으면 중단 안내(§6)
  2. 앱 탐지: Claude 데스크톱·Codex 앱 설치 여부 확인 → 없으면 공식 다운로드 링크 안내
  3. 관리자 승인 1회(UAC): 선택된 Stata 실행파일로 /Register(COM 등록)
  4. 서버 배치: %LOCALAPPDATA%\StataAgent\stata-agent-mcp.exe 복사
  5. Claude 연결: .mcpb 자동 실행(설치 대화상자) 또는 설정 파일 병합(기존 설정 백업 후)
  6. Codex 연결: Codex 설정 파일에 [mcp_servers.stata] 병합, 스킬 폴더에 SKILL.md 복사
  7. Claude 스킬: 설치 완료 화면에서 stata-analysis.zip 위치를 열어 주고 "Customize > Skills > 업로드" 1회 안내
  8. 작업 폴더 생성: 문서\StataAgent\예제에 auto 예제 프로젝트(§10 규약) 생성
  9. 완료 점검: 앱 재시작 후 채팅에 "Stata 연결 확인" 입력 → stata_status 결과 표시

설정 파일 변경 직후 앱 연결이 끊기는 현상을 오늘 실제로 겪었음 1차 확인 → 설치 마지막 단계에서 "앱 완전 종료 후 재실행"을 반드시 안내.

Phase 0(§2) 시험은 개발자 PC가 아니라 깨끗한 Windows PC(또는 가상 PC) + Claude Pro 계정 1개 + ChatGPT Plus 계정 1개로 수행해야 "아무것도 없는 상태" 전제를 검증할 수 있음. 원내 보안 프로그램(AppCheck 등)이 설치된 업무용 PC 1대에서 추가 시험 필요.

1. 목표와 운영 원칙

목표

  • PC에 설치된 Stata 버전·에디션(BE/SE/MP, 17~19 및 StataNow)에 관계없이 작동하는 Stata 연결 MCP + 분석 스킬 패키지 구축
  • Claude(유료 요금제, Claude Code)와 GPT(유료 요금제, Codex) 모두에서 동일 패키지로 에이전트형 분석 수행
  • 연구자는 채팅으로 요청 → AI가 do-file 작성·수정 → Stata가 계산 → AI가 로그를 읽어 검증·해석 → 논문형 표·초안 산출

운영 원칙 (설계 전체에 적용)

원칙내용구현 장치
P1 계산 주체모든 통계량은 Stata가 산출. AI는 코드 작성·결과 판독·해석만 담당. AI가 수치를 직접 계산·추정하여 보고하지 않음스킬 규칙 + 해석 시 로그·저장결과 인용 의무
P2 원자료 비전송개별 관측치(행 단위 값)는 AI 모델로 전송하지 않음. 요약통계·검정통계량·메타데이터만 전송MCP 명령 차단(guard) + 데이터 조회 도구 제거(§8)
P3 사람 승인실행 전 코드를 연구자가 확인·승인클라이언트 권한 설정(실행 도구 = 승인 필요)
P4 가시성AI가 연 Stata 창(Results·Do-file Editor)에서 결과를 사람이 직접 확인·이어서 작업COM 기반 GUI 세션(§3·§5)
P5 재현성모든 분석은 do-file로 남고, 00_master.do 1회 실행으로 전체 결과 재생성폴더·do-file 규약(§10)
P6 투명성AI 사용 내역(도구·반복 횟수·산출물 보존) 기록 → 논문 Method 절 공개 지원세션 기록 파일 + 공개문 초안 생성

2. 선행 기반(Phase 0): 채팅–Stata 실시간 연동

패키지·스킬 개발 이전에 아래 4개 동작이 하나의 Stata 창에서 끊김 없이 작동해야 함. 이 단계 통과가 이후 모든 작업의 전제임.

#요구 동작합격 기준현재 상태
F1AI가 Stata 창을 열고 자료를 로드, Do-file Editor에 do-file 표시창 1개에 Results·Do-file Editor가 열리고 자료 로드 메시지 확인1차 확인 부분 작동(새 창 방식, §2.1)
F2채팅 요청("상관분석 추가")만으로 do-file 수정·추가 → 같은 창에서 즉시 실행새 창 생성 없이 동일 세션에서 실행, 이전 메모리(자료·추정결과) 유지미확인 COM 세션 방식으로 해결 예정
F3수정된 do-file 내용이 Do-file Editor 화면에도 반영편집기 탭이 최신 내용으로 갱신(중복 탭 미발생)미확인 외부 수정 시 편집기 자동 재로드 여부 검증 필요
F4실행 결과를 AI가 읽고 채팅창에 검증·해석 제시로그 수치와 채팅 해석 수치 일치, 가정 위배 지적·수정안 제시1차 확인 로그 판독 방식으로 작동

2.1 오늘 시험에서 확인된 사항 (2026-10-29)

항목결과
배치 실행 → 로그 판독 → 수정 → 재실행1차 확인 desktop-commander(범용 셸 MCP)로 StataMP-64.exe /e do 실행, 로그 판독, 분산분석 등분산 위배 감지 후 수정안(Levene·병합·강건F·Kruskal-Wallis) 재실행 성공
버전 간 재현성1차 확인 Stata 18 SE와 StataNow 19.5 결과 로그 수치 완전 일치(자료 파일 날짜 표시 1줄 차이만 존재)
GUI 표시1차 확인 StataMP-64.exe do file.do + do-file 내 doedit로 Do-file Editor·Results 표시. 단 호출마다 새 창 생성
배치 로그 이름 충돌1차 확인 /e 실행 시 do-file명과 같은 이름의 로그를 Stata가 자동 생성 → 분석 로그(log using)를 덮어씀. 분석 로그는 별도 이름 필수
라이선스 만료 감지1차 확인 만료 시 배치 로그에 request ignored because of batch mode 출력 후 중단 → doctor 점검 항목에 포함 필요
범용 셸 MCP 권한논리적 추론 PC의 모든 명령 실행 가능·승인 단계 없음 → 패키지에서는 Stata 전용 도구로 권한 축소 필요
클라이언트 설정 변경 영향1차 확인 Claude Desktop 설정 파일 수정 직후 원격 PC 도구 연결 단절 발생(원인은 논리적 추론: MCP 재로드) → 설치 스크립트는 "설정 변경 후 클라이언트 재시작" 안내 필수

2.2 Phase 0 시험 시나리오 (구현 직후 수행)

  1. 채팅: "auto 자료 열고 기술통계 보여줘" → 창 1개 생성, Do-file Editor에 01_*.do 표시, Results에 결과
  2. 채팅: "가격을 종속변수로 회귀 추가" → 같은 do-file에 섹션 추가, 같은 창에서 해당 블록만 실행, Editor 갱신
  3. 채팅: "이분산 확인하고 필요하면 고쳐줘" → 진단 실행 → 로그 판독 → 강건표준오차 수정안 → 승인 후 실행

6. Stata 버전 무관 탐지·연결

  1. 설치 탐색: C:\Stata*, C:\StataNow*, C:\Program Files\Stata*, C:\Program Files (x86)\Stata*, 레지스트리 COM 등록 경로 → Stata(MP|SE|BE|IC)?-64.exe 목록화 1차 확인(이 PC: C:\StataNow19, C:\Stata18, C:\Stata17 존재)
  2. 라이선스 확인: 각 실행파일로 about 배치 실행 → 버전·에디션·만료일·등록자 파싱. 만료 시 제외 1차 확인(배치 about로 만료일 확인 성공)
  3. 우선순위: 사용자 지정 > 유효 라이선스 최신 버전 > MP > SE > BE
  4. COM 등록 대상 고정: 선택된 실행파일로 /Register. ProgID가 하나이므로 마지막 등록본이 기본이 됨 논리적 추론 → doctor가 현재 등록 경로를 표시
  5. do-file 버전 선언: 선택 버전으로 version NN 자동 기입(19.5 StataNow는 version 19.5 또는 19)
  6. 라이선스 등록자 표시: doctor 결과에 등록자 노출 → 기관 라이선스 여부 사용자 확인(오늘 시험에서 타 기관 등록 설치본 발견)

  • 로그는 이름 지정 로그(name()) 사용 → MCP 로그와 충돌 방지
  • 원 결과 섹션은 삭제하지 않고 수정 섹션 추가(분석 이력 보존)

11. 클라이언트 설정 (Claude Code · Codex)

아래 명령은 개발·시험용임. 최종 사용자는 명령을 입력하지 않으며, §0의 설치 프로그램이 같은 내용을 자동 기록함.

Claude Code

claude mcp add --transport stdio --scope user stata -- stata-agent-mcp
# 스킬: .claude/skills/stata-analysis/SKILL.md (또는 사용자 범위)
# 권한: 실행·쓰기 도구는 ask, 읽기 도구(status·schema·read_log·get_results)는 allow

Codex

codex mcp add stata -- stata-agent-mcp
# 또는 ~/.codex/config.toml
[mcp_servers.stata]
command = "stata-agent-mcp"
args = []
# 스킬: .agents/skills/stata-analysis/SKILL.md

명령·경로는 stata-gui-mcp 문서와 제3자 정리 자료 기준 검색 확인. Codex의 도구별 승인 정책 설정 방식은 미확인 → 구현 시 공식 문서 확인.

스킬 공용화

  • SKILL.md 본문은 단일 원본 유지, 설치 스크립트가 두 경로(.claude/skills·.agents/skills)에 복사
  • 클라이언트별 차이(도구 접두어 mcp__stata__ 등)는 SKILL.md 내 분기 문단으로 처리
  • configure_clients.py는 기존 설정 백업 후 병합(덮어쓰기 금지), 완료 후 "클라이언트 재시작" 안내

13. 작동 점검·자가 진단 체계

점검은 세 층으로 나눔: ① 사용자가 채팅 한 줄로 실행하는 자가 점검, ② 문제 발생 시 공유하는 점검 보고서, ③ 개발자가 배포 전 수행하는 출시 전 검수.

13.1 사용자 자가 점검 (채팅: "Stata 연결 점검해줘")

#점검 항목방법통과 기준실패 시 안내
T1Stata 설치·라이선스탐지된 실행파일로 about버전·에디션 표시, 만료일이 오늘 이후라이선스 갱신 안내
